# 시멘틱 단계 실행 계약

SION `251a61d2b739db9dcee72b0ce0c9b0ddf82cfe63`의 현재 구현을 설명합니다. 실행 형식은 `SIGMA_SEMANTIC@v1`, 공통 정의 형식은 `SIGMA_SEMANTIC_DEFINITIONS@v1`입니다. 기존 객체 모델과 별개로 [공통 의미 정의](../01_모델정의/semantic_definitions.json) 17개를 `agent/config/ontology/semantic_definitions.json`에 배치합니다. 객체 모델에 새 타입을 추가했다고 해석하지 않습니다.

## 실행과 제출

`agent/run.py`는 `decide`·`view`에서 기본적으로 `semantic_runner.run`을 사용합니다. 실행기가 하나의 `run_attempt_id`에 대해 interpretation, bull, bear, lead를 별도로 호출합니다. 역할은 `SION_SEMANTIC_ROLE`로 부여하고 역할마다 도구를 제한합니다. bull·bear·regime 지침은 기존 `.claude/agents` 파일에서 읽습니다. 네 호출은 `MAX_BUDGET_USD`와 회차 25분 제한을 공유하며, 비용을 확인할 수 없으면 다음 호출로 진행하지 않습니다.

| API | 계약 |
|---|---|
| `get_semantic_context(code, confidence_for)` | 인수를 생략하면 대상 목록, 명시하면 정의·실효 기준·수락된 선행 단계·해당 역할 계약과 `input_id` 반환 |
| `submit_semantic_stage(input_id, data)` | 해당 회차·역할·입력 해시·선행 단계·참조·필수 필드 검증 후 수락 또는 오류 반환 |
| `get_semantic_trace(code, confidence_for)` | 현재 회차의 명시적 단계 연결과 저장된 무효화 상태 조회 |

`context`는 입력을 저장한 다음 반환합니다. 수락된 단계는 같은 내용으로 재시도할 수 있고 다른 내용으로 덮어쓸 수 없습니다. 거절은 별도 실패 기록으로 남습니다. 최종 lead 수락이 `judgment_id`를 생성하며 strict 실행에서 직접 `record_ai_judgments`를 호출할 수 없습니다.

## 공통 맥락·평가·채택

공통 맥락에는 의미 정의·실효 매수 기준·정책·리스크 설정·국면과 관련 소스 해시가 포함됩니다. 주장은 기존 사실/인용/가설 계약과 근거 전달 계약을 사용합니다. 단위·대상 및 제출한 측정 맥락은 전달된 자료와 대조하며, 가설과 인과 경로의 참은 인증하지 않습니다.

interpretation은 주장과 경로를, bull·bear는 받은 모든 경로에 대한 평가와 생성한 반론을 제출합니다. 반론의 빈 목록은 생성된 반론이 없다는 뜻입니다. 총괄은 모든 평가·반론을 `adopted`·`rejected`·`deferred`·`unreviewed`로 처리하고 이유를 남깁니다. `strong`에는 양측의 매수 해석 동의뿐 아니라 해당 지지 평가와 연결 주장의 실제 채택이 필요합니다. 확정 위험 경로에는 채택한 반대 평가와 주장 연결이 필요하며 불확실한 경로 묶음은 정확한 위험 개수로 확정하지 않습니다.

확신도는 기존 지침의 구간과 AI 재량을 사용합니다. 새로운 위험 확률·가중치·수량 산식을 추가하지 않습니다. 기록과 스키마 수락은 투자 주장의 진실, 시장 인과, 모델의 내부 사고를 입증하지 않습니다.

## 대상과 후속 실행

해석 단계는 실제 브리핑·계좌 조회 후 목록을 다시 확인합니다. 보유 종목은 매도와 조건부 추가 매수 검토를 따로 등록합니다. 추가 매수 검토가 실제 매수 허용을 뜻하지 않으며 기존 add-on 설정과 리스크 검사가 적용됩니다. bull 이전 목록을 고정하고 새 대상 발견 시 `SEMANTIC_TARGET_SET_CHANGED_RESTART_REQUIRED`로 중단합니다. 이전 판단·주문을 덮어쓰지 않고 새 시도에서 최신 계좌와 미확인 주문을 확인합니다.

계획·주문·비주문 기록·주문 Hook은 수락된 판단의 회차·종목·방향과 원확신도를 검사합니다. 모든 대상·방향에 성공한 `record_decision` 또는 `place_order` 결과가 필요하며 `plan_order`만으로 완료되지 않습니다. `view`는 비주문 기록만 허용합니다. 보호 청산은 별도 `exit` 실행의 기존 절차입니다.

## 저장·재평가·조회

기록은 온톨로지 저장소의 `semantic/<run_attempt_id>/` 아래 chains, inputs, stages, failures, consumptions, scope, invalidations 및 run 기록으로 저장됩니다. 저장 v2의 공통 객체와 원본 입력 보존 계약을 함께 따릅니다. 현재 정의·정책·국면·코드가 바뀌거나 해당 체인이 무효화되면 과거 판단의 후속 사용이 거절됩니다.

과거 단일 판단 조회는 `agent/tools/semantic_reassessment.py --judgment-id JUDGMENT_ID`를 사용합니다. 신뢰된 로컬 정정은 `--invalidate DEPENDENCY_ID --chain-id CHAIN_ID --reason 사유`로 명시한 체인에 한정합니다. 실행 전에 대상 저장소·체인을 확인합니다. 이 도구는 모델 호출이나 주문 취소를 하지 않습니다. 과거 조회의 `not_invalidated`는 저장된 무효화 기록 부재를 뜻하며 현재 실행 자격 인증이 아닙니다.

## 설정과 검사 도구

`SION_SEMANTIC_MODE=legacy`는 단계 실행 호환 모드이며, `SION_EVIDENCE_WIRE_FORMAT=legacy`는 근거 전달 호환 모드입니다. 어느 쪽도 코드·데이터 롤백을 대신하지 않습니다. 역할·회차 식별자는 실행기가 설정하며 운영자가 임의로 재사용하지 않습니다.

`agent/tests/conftest.py`는 과거 검사에는 legacy를 명시하고 semantic 표시 검사에는 strict를 적용합니다. 신규 회귀 검사는 `test_semantic_layer.py`, `test_semantic_review_regressions.py`에 있으며 프롬프트·브라우저 계약 검사도 함께 변경됩니다. `tools/rehearse_semantic.py`는 시험 fixture와 격리 폴더를 사용하지만 실제 Claude CLI를 호출하므로 유료 모델 리허설에 해당합니다. 일반 pytest 실행에 포함되지 않으며 이 추출 작업에서는 실행하지 않습니다.
